# Blind voting API

Deploy the Worker and D1 migration only after populating `catalog.js` with the exact public versioned dataset and candidate-to-method mapping. The empty catalog rejects all datasets. Replace `REPLACE_AT_DEPLOY` with the created D1 database ID and set `VOTE_SALT` as a secret. `ALLOWED_ORIGIN` must exactly match the public site origin. `DEV_ORIGIN` is optional and only accepts an exact localhost or 127.0.0.1 origin. No credentials belong in this repository. Apply `migrations/0001_votes.sql` before serving requests.

Requests with a disallowed Origin are rejected; writes require an allowed Origin, `application/json`, and a body of at most 4096 bytes. GET `/health` returns `{ok:true}`. GET `/stats?dataset=blind-v1` returns `{dataset,totalVotes,participantBrowsers,methods,fragments}`, where `methods` and each `fragments[fragmentId]` have integer `skilled`, `published`, `baseline`, and `reviewed` counts. Unknown or empty datasets return 404.

POST `/votes` takes `{dataset,fragmentId,candidateId,participantId,voteId}`, with UUID participant and vote IDs. Success, including retries, returns 200 `{dataset,fragmentId,candidateId,voteId}`. Another choice for the same browser and fragment returns 409 `{error:"already_voted",candidateId}`; a vote ID belonging to a different vote returns 409 `{error:"vote_id_conflict"}`. DELETE `/votes` takes `{dataset,participantId}` and returns `{dataset,deletedVotes}`. Errors have `{error}`; more than 100 vote attempts per IP per UTC day return 429, including idempotent retries. Deletions use a separate daily bucket.

Migration `0002_erasure.sql` adds a hashed erasure tombstone. Erasure and vote deletion are transactional, so an in-flight delayed vote cannot recreate erased choices. An old erased participant receives 410 `participant_erased`; the frontend starts a new identifier after a successful erase. Vote and deletion rate buckets are separate. `/stats` derives grouped counts and distinct browser count from one SQLite read snapshot.

The database stores an HMAC-SHA256 participant key scoped to the dataset, a random vote UUID, the choice and timestamp; it stores neither the participant UUID nor the IP address. An HMAC-SHA256 of the IP and UTC date is retained for rate limiting, expiring after 48 hours and cleaned on a subsequent write. `VOTE_SALT` must be a strong, unique secret. Changing it makes existing participants unable to retry or delete their earlier votes and resets rate buckets; plan rotation accordingly. Voting is pseudonymous, not anonymous against an operator with the salt and outside information. The rate limit is a practical abuse bound, not protection against multiple networks, browsers, cleared storage or deliberate manipulation. A participant can delete their votes only while retaining their browser ID. Aggregates reveal no individual rows, although small counts may reveal choices in context.
